# 索降作业三段计时与「可卸 / 可换 / 盈利」可行域（接续版）

2026-09-26。实现：`public/drone-logistics/winch.mjs`（浏览器）与 `winch_studies.py`（Python 参考），
对偶测试 `scripts/test-drone-winch.mjs` / `dashboard/tests/test_winch_studies.py`。
主模型通过 `operation_mode`、`enforce_winch` 两个开关接入同一套推导，见第 4 节。

本文件取代 `public_data_update.md` 中「下一步的最小研究设计」一节所列的待办，并落实该节指出的
流程问题：**原版把「卸货并装货」当作一个固定作业周期，厂商公开资料没有证实同一个悬停内换货可行**。

## 11.1 公开数据锚点与情景假设必须分开

| 量 | 取值 | 来源性质 |
|---|---|---|
| 参考性能点 | 20 kg / 70 km | 原文表 2（丰舟 90） |
| 绞盘投送、收回上限 | 5 kg | A2Z RDS2 公开规格页；**另一厂商产品** |
| 绞盘主体带罩 | 1.5 kg | 同上 |
| 自动释放钩及配重 | 0.264 kg | 同上 |
| 2 kg 货物、约 20 m 高度：离机到空钩收回 | 41 s | 同上产品页图表，**单次投送**口径 |
| 2 kg 货物、约 30 m 高度 | 62 s | 同上 |
| 取货时间、地面换货时间 | 无 | 完全无公开数据 |
| 接近、机型转换、退出时间 | 无 | 完全无公开数据 |
| 装卸增量耗能 e₀、e_d、e_l | 无 | 无实机依据 |
| 每 kg 净贡献 c_d、c_l、固定成本 F | 无 | 运营场景数据 |

上图两条观测**只覆盖单一质量（2 kg）与单一绞盘（不是丰舟 90）**，因此只能定出高度灵敏度，
不能定出质量灵敏度，更不能证明本机可改装。

## 11.2 高度律：两点定一条直线，并显式记录它的病态

两条观测同为 2 kg，令每 kg 投送时间随高度线性：

```text
τ_ref = 41 s ÷ 2 kg = 20.5 s/kg          （在 h_ref = 20 m）
κ     = (62 − 41) s / (41 s × (30 − 20) m) = 0.05122 /m
τ_d(h) = τ_ref · (1 + κ (h − h_ref))  =  b·h + a
       b = τ_ref·κ = 0.0175 min/(kg·m) = 1.05 s/(kg·m)
       a = τ_ref(1 − κ·h_ref)/60 = −0.008333 min/kg
```

**截距 a 为负**，这是外推产物而不是物理结论：真实关系里必定存在一个正的固定项（挂钩、放钩、确认）。
在拿到第三个数据点（不同质量，或不同机型）之前，`τ_ref`、`κ` 与 `h_ref` 都作为可改的情景参数暴露，
不要把它们当成丰舟 90 的标定值。为避免出现「抬得越低反而越快」的假象，程序在 τ(h) < 0 时把它夹到 0
（对应 h < 0.476 m），并在返回值里用 `tau_clamped` 标记。

取货时间默认沿用同一个高度律，这**没有公开数据支持**，是明确的情景假设。

## 11.3 约束：把作业拆成三段而不是一个固定周期

```text
T_total = T_approach + T_transition + T_drop(d,h) + T_exchange(d,l) + T_pickup(l,h) + T_exit
          ≤ min(W, H)        （占用机场共享空域时；机场外独立卸货区只用 W）

T_drop(d,h)     = τ_d(h) · d
T_pickup(l,h)   = τ_l(h) · l
T_exchange(d,l) = ex₀ + ex₁ · (d + l)      （无公开数据，纯情景）
```

质量与能力上限：

```text
m_hw = 1.764 kg                       （如同时使用上述主体与自动释放钩）
d ≤ min(winch_capacity, D, B, m_budget)
l ≤ min(winch_capacity, L, B, m_budget)
m_budget = 参考净载荷 − q − m_hw − m_box − m_mount
```

`m_box`、`m_mount` 分别是新货仓与安装件质量，**现无公开值**。原文 20 kg 是厂家 70 km 对应点；
若 q=10 kg、d=5 kg，扣掉 1.764 kg 硬件后，留给 m_box+m_mount 的名义空间只有 3.236 kg。
这只是必要的名义载荷条件，不保证任何实际索降任务可飞。

能量沿用主模型口径 `e₀ z + e_d d + e_l l ≤ G`（分区面板里 G 已扣除 e₀，见下）。

**后一情形的时序约束应显式写成三段**，而不是原来的单一固定周期；若机械设计必须先收钩再放钩，
`T_drop` 与 `T_pickup` 应各计一次完整绞盘循环。作业模式必须在试验设计里写清楚。

## 11.4 分区与阈值：先固定 z=1 求最优，再和「不作业」比较

固定 z=1 后是二维线性规划，可行域为

```text
0 ≤ d ≤ cap_d,  0 ≤ l ≤ cap_l
(τ_d(h)+ex₁)·d + (τ_l(h)+ex₁)·l ≤ W_free
e_d·d + e_l·l ≤ G_free
```

其中 `W_free = min(W,H) − (approach+transition+exit+ex₀)`、`G_free = G − e₀`。
程序枚举全部边界交点求精确最优，再与 z=0（收益 0）比较。逐格分类为五类：

| 类 | 含义 |
|---|---|
| 0 | 最优解 d>0 且 l>0，净收益为正 |
| 1 | 最优解 d>0 且 l>0，净收益非正 |
| 2 | 最优解仅卸货（l=0），净收益为正 |
| 3 | 最优解仅卸货，净收益非正 |
| 4 | 不作业 / 不可行 |

**必须同时看「能做」和「能做满」两套口径。** 只要允许任意小的 d>0，「可卸」几乎总是成立，
所以分区占比会远大于「满额作业」占比；判断作业能力应以满额阈值与 `cap_d`、`cap_l` 为准。
阈值统一返回 `{value, status}`，`status` 为 `found` / `beyond_upper` / `lower_already_false` 等，
避免把「搜索上界外仍然可行」误读成具体数值。

默认参数（q=10、h=20 m、W=H=6 min、G=0.65 kWh、e₀=0.1、e_d=0.04、e_l=0.08、c_d=4、c_l=3、F=5）下：

- `cap_d = cap_l = 5 kg`（绞盘上限绑定；质量余量 8.236 kg 不是瓶颈）；
- 满额（d=l=5 kg）需要 `G ≥ 0.7 kWh`，而默认只有 0.65，所以**满额受限于装卸新增电量预算**；
- 盈亏平衡窗口约 0.43 min，远小于默认 6 min——也就是说默认情景下「作业划得来」不是瓶颈，
  **瓶颈是能不能做满**。

## 11.5 与主模型的关系

主模型新增两个开关，默认都为 0，因此**不改变任何既有结论与已发布数字**：

- `operation_mode`：0 = 原来的「一次固定悬停换货」（`t₀ + t_d d + t_l l`）；1 = 本节的三段计时。
- `enforce_winch`：0 = 不做绞盘与改装质量检查；1 = 加上 `winch_capacity` 与 `m_budget` 两道上限，
  并在约束检查里新增「绞盘投送上限」「绞盘收回上限」「索降改装质量预算」三行。

实现方式是先把三段计时折算成等效的 `(t₀, t_d, t_l, D, L)`，再交给同一个精确顶点枚举求解器，
因此没有第二套求解逻辑，浏览器与 Python 的 77 个跨实现场景逐字段一致。

注意两处口径差异，写论文时要说明用的是哪一个：

1. 主模型的可用电量含编队基准节能余量 `S₀ = (1−γ)[k₀ R_CB + a_l q]`，分区面板不含；
2. 主模型的质量预算以 `effective_q = min(Q, min(20, 37.5−R/4) − equipment_mass)` 为基数，
   分区面板以参考性能点 20 kg 为基数。若两者都填了设备质量，会重复计入——
   用绞盘分项时把 `equipment_mass` 置 0。

## 11.6 本模块仍未覆盖的

- 吊索摆动、风场、地面接货容量、多机同时索降的空域冲突；
- 绞盘可靠性、故障缓冲与备件；机械接口是否允许同一仓在地面换货而不收回空钩；
- 丰舟 90 的改装兼容性、改装后电池余量与悬停功率；
- 因此结论只可表述为「在给定假设下存在正收益方案」，**不可表述为真实丰舟 90 索降一定盈利**。
