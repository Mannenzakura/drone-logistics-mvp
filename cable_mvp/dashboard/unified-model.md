# 运输决策与全天运营联合实验（2026-10-03）

## 五步的统一口径

1. 路线、装卸和全天运营共用 `eventSchedule` 与 `networkLedger`。一天产生需求，模拟到1530分钟以清空尾段；收入和成本属于这一天产生的任务批次，并非严格午夜结账。
2. 取每天第一架A→B任务作追踪任务，比较D/E路线与原可选装卸量的0、50%、100%。其余任务不改。没有A→B任务的样本不强行增加任务，追踪指标只对存在追踪任务的样本统计。
3. 核查交付收入、时效损失、处理费、作业费、电费、未完成罚损、救援、设备、机场、领航、充电、地面设施与维修成本。同时记录实际发车、空班和席位利用率。
4. 比较固定班次、按时段班次、人数/最长等待触发班次。按时段策略高峰使用基本间隔，普通时段两倍，夜间四倍。按需策略每分钟检查当前队列，人数阈值3、等待阈值10分钟，并受最小发车间隔约束。阈值不是交付保证。
5. 比较六种资源包、三种发车规则、两种运输规则；含充电资源的方案再比较下一航段、剩余行程和充满策略，共60个离散候选。探索样本按总体可靠性下界筛选后，选平均全网净收益最高者，再用独立样本固定复核。

## 在线决策的信息与边界

决策只发生在适用的A/C→B任务产生时。使用当时已产生的任务状态、公开班次机会、已知距离、载重和能耗参数，比较D/E与三个可选货量比例。不读取未来随机到达名单。最终运行仍由事件引擎决定排队、起降、充电、错过编队和交付结果，预测不能替代实际仿真。

主任务的货物重量和订单数始终保留。装卸量变化针对每任务随机生成的附加货物机会，不代表删去难交付的主订单。当前假设两条分支均有相应货物机会，尚未建立站点共享库存或货物目的地匹配；因此该部分是需要进一步验证的供给假设。

这是有限网格与在线启发式比较，没有连续全局最优证明。配置选择也不是全部设备规模、全部班次和任意装卸量的穷举。

## 统计与可靠性

默认探索种子893104，复核种子993104，各30个独立日样本；两组种子互不重叠。各方案使用相同背景需求作配对比较。可靠性区间以每天的交付比例为样本计算近似95%区间，不把相关飞机误当作独立样本。普通货物未服务比例的变化也作配对复核。扰动使用相同复核需求，额外加入天气/故障；不根据压力测试结果重新选择方案。

总体90%门槛不等于每一货类都达到90%。医疗期限45分钟、快件60分钟、普通90分钟。部分A→B任务单纯飞行与垂直起降时间已超过医疗期限，扩容不能解决这种物理不可行性。

## 默认30日复核示例

扩大资源、按时段发车、全机队在线选路装卸的正常平均交付率96.67%，近似95%下界95.90%；平均全网净收益148.24元/当天任务批次。扰动平均交付率95.78%，下界94.78%。这些结果只适用于当前假定参数，不能作为真实机场盈利或可靠性证明。

正常样本医疗166/239（69.46%），快件660/663，普通1366/1366。必须保留分货类结果；不能用总体达标掩盖医疗服务不足。候选的空班比例仍然较高，发车加密并不必然提高席位利用率。

## 账本修复与验证

修复未开始作业的空时间被当作零而错误计费的问题；电量停止任务现在计入设定的救援估计。救援价格是假定的恢复费用，并非实际救援报价。费用恒等式、电费逐任务求和和任务ID唯一性均核验。

27个现有及新增JavaScript测试通过。新增手算检查覆盖未来信息隔离、可选货量上限、按需最长等待触发、无空班触发、未作业不计费、电量停止救援费、独立种子和主任务守恒。
